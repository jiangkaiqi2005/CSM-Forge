# CSM-Forge 完整技术总纲

规范版本：2.0-design。代码核对基线：`225fd25151fb6ec0a8dae3e95ca2945fb4270462`。状态：技术路线已决定，以下新增能力仍待实现与验收；不是可游玩版本的功能声明。

## 1. 产品目标与范围

目标是 Cities: Skylines 1 的长期可维护多人共同经营系统：一个 Host 运行权威城市，多个 Client 同时编辑、观察并参与正在推进的城市。多人可以在游戏进行中并行进入；一名加入者下载慢、加载慢、取消或断线，不得让其他加入者串行等待，不得让已在游戏中的玩家等待其完成。

首个对玩家发布的目标配置为 Windows x64、四人房间（含主机）、至少两名玩家并行加入、经过验收的游戏版本/DLC/资产组合。八人和跨平台是后续扩展，不把当前 `Limits.Peers = 8` 当作八人实测支持。暂停编辑只是内部垂直切片，不能以它替代实时多人产品目标。

支持范围按能力发布，不声称立即覆盖游戏全部 DLC、地图规模、工具和第三方 Mod。未覆盖的操作必须被主动阻止；任何限制都要在开房前列出。正常联网中不因加入者等待而全房暂停；快照自身可能需要有界本机一致性安全点，详见并行加入规范，不预先承诺未经测量的零停顿。

## 4. 权威与一致性模型

保留单主机单写者，不引入分布式共识或双主。网络层提供身份和消息，不能成为城市权威。Host 不等待每个 Client 确认才推进模拟；Client 不参与权威提交投票。主机是信任边界，不承诺抵御恶意主机篡改自己城市。

三类序列必须分开：认证连接的消息序列、玩家意图的操作计数、世界结果的 CommitRevision。SimulationTick 只是模拟时间；一次 tick 可以产生多个独立可发布批次，也可能没有持久变化。跨领域关联修改必须在同一个原子可见批次中提交，不能让一个中间状态成为快照或哈希比较的基线。

安全不变量：设 `S_B` 是已验证快照，`C_(B+1)..C_R` 是连续结果，则副本 `S_R = Apply(S_B, C_(B+1)..C_R)`。只有其规范化根等于 Host 在 R 保存的根，且游戏投影已经发布，才确认 Applied(R)。这一等式只对声明并完整覆盖的状态闭包成立；不得将小部分字段哈希外推成整座城市一致。

依赖全游戏确定性 lockstep 的路线继续舍弃。自有状态编码、结果应用和模型测试必须可重复；主机游戏模拟的内部实现不需要在每个 Client 被重新执行。Hash 不能替代状态复制或完整覆盖，只是检查已定义状态关系的证据。

## 5. 持久事实与表现

游戏事实是会影响后续决策、费用、引用、任务、生命周期或保存的状态；不局限于磁盘上原生保存的字段。道路、建筑、居民/车辆的任务与生命周期、经济、资源、运输、分区等都要有明确权威归属。

可见车辆/行人位置、远端光标和工具预览可以有单独的表现流与插值。但同一位置若影响寻路、碰撞或游戏决策，Host 的真实位置仍是游戏事实；客户端画出来的位置不能写回模拟。视觉一致不能代替规则一致。

项目维护领域覆盖表、因果引用图和适配器验收证据。扩大兼容范围时先补状态闭包与恢复闭包，再添加 UI 或放开工具。详见运行时规范。

## 6. 并行加入的基准决策

每个加入者拥有独立的 `(WorldId, Epoch, MemberId, ConnectionBinding, JoinId, JoinGeneration)`。快照文件可以按 SnapshotId 共享，传输与日志游标不能共享。缓存采用引用计数和有时限租约，取消一人只释放其引用。

Host 为快照 B 保留 B 之后的提交；加入者安装 B 后追赶连续结果。Host 为该加入者发出固定 Barrier H，保存 R(H)，验证客户端对 H 的确认，而不是再次比较当前最新头。激活授予在同一个有序状态流内建立明确发布边界 A。其他加入者、慢客户端与后续提交都不改变 H 的含义。

多人并行不意味着同一个 CS1 进程同时加载多个城市，也不意味着多线程并发写 Manager。每个 Client 在自己的进程中加载；Host 的本机原生快照生成器可以是单工作者，但共享产物后多个下载和追赶必须并行。不得用全局 `isJoining` 或“等所有人 Loaded 再恢复模拟”实现正常加入。

## 7. 模块与部署

产品先保留游戏内托管核心与窄 GameNetworkingSockets 原生适配，不在本轮额外引入外部代理服务架构。原生 ABI、库命名和旧 Mono 支持必须先验证；不替换游戏的 steam_api 或共享 Harmony 库。原生崩溃无法被托管 finally 可靠恢复，仍须按检查点恢复；该风险有独立验收和发行阻断条件。[S-GNS][S-HARMONY]

| 目标模块 | 所有权与职责 | 禁止越界 |
| --- | --- | --- |
| Forge.Core | 纯模型、状态机、权威批次、操作账本、状态根 | 不读 Unity/游戏对象，不开 socket |
| Forge.Protocol | v1 兼容测试边界、独立 v2 DTO/有界 codec | 不动态执行反射方法，不决定权限 |
| Forge.Sessions（新增） | Membership、JoinContext、恢复、屏障与事件路由 | 不在网络线程修改世界 |
| Forge.Replication（新增） | 领域批次、闭包、版本化根、游戏投影应用状态 | 不擅自解释网络 ACK 为应用成功 |
| Forge.Checkpoints（新增） | 不可变快照索引、租约、日志存储、原子发布 | 不在后台遍历正在变化的游戏对象 |
| Forge.Transport.Gns（新增） | 原生 ABI、身份连接、IO 轮询、通道调度与统计 | 不分配城市 Revision |
| Forge.Runtime.Cities1 | 生命周期、线程调度、隔离补丁、真实 Manager 适配 | 不直接复制客户端工具调用作为结果 |
| Forge.Compatibility（新增） | 实际采集、支持目录、能力映射和配置指纹 | 不把相同 Mod 列表等同于已支持 |
| Forge.UI（新增） | 房间、进度、权限、操作回执与诊断出口 | 不先本地提交再等待主机“纠正” |
| Forge.Tests / Lab | 故障链路、虚拟时间、模型与真实适配边界测试 | 不把测试替身声明为实机成功 |

新增模块先按命名空间/目录拆职责，在实际形成独立依赖边界时再拆程序集；不为了图好看产生空项目。GNS 网络工作者持续轮询，加载游戏也不能停止网络生命维持。UI 主线程和模拟线程的消息边界分别管理；任何 I/O 都不得持有游戏世界锁等待对端。[S-STEAM]

房间服务只负责发现、短期授权、信令和中继分配，不运行城市。没有中继不应宣称所有校园网/对称 NAT 均可直连；没有 Steam 平台授权不默认拥有 SDR。联网运维与认证设计见协议规范。

## 8. 接口契约（待实现）

这些是目标契约，不是当前已有 API：

- `IJoinCoordinator.Begin/Cancel/OnProgress/OnBarrierAck`：每次返回或消费明确 JoinIdentity；以单调时钟判断期限；终止操作幂等。
- `ICheckpointCatalog.AcquireCompatible/Release`：返回不可变 CheckpointHandle 和租约；不得把另一客户端的取消传播给公共产物。
- `ICommitStore.ReadRange/AcquireRetention/Append`：按 Epoch+Revision 读取连续区间；超出保留范围返回明确类型，不返回“空数组表示成功”。
- `IAuthorityBatchCapture.Begin/Seal/Abort`：捕获玩家操作或自然模拟结果；Seal 包含修改的全闭包、前后根、Schema；部分失败必须显式 Fenced。
- `IReplicaApplier.Stage/Publish/Verify`：只在候选状态完整时发布；成功不仅指 Forge 镜像已更新，还包括游戏投影已生效。
- `IGameThreadDispatcher.TryPost`：绑定 World/LoadGeneration，按时间与字节预算处理；卸载时旧任务永久失效。
- `ISimulationIsolation.Enter/Probe/Leave`：进出联机按实际角色建立写屏障；无法证明隔离则不开启相应产品能力。
- `IOperationLedger.Resolve`：返回 committed/rejected/expired/unknown，不凭断线推测“肯定没执行”。

接口都需要取消、容量失败、过期代次、重入和 owner-thread 违例的测试。跨线程交接仅使用不可变 DTO、句柄和已冻结字节，不传 Manager、Unity 对象或共享 BinaryReader。

## 9. 当前内核的明确改造点

| 当前 M0 行为 | v2 所需变化 |
| --- | --- |
| `CompleteJoin` 要求 ack.Revision == 当前 Revision | 以租约内固定 H 的根校验，并独立授予激活边界 A |
| 单一 Ready bool | 区分成员准入、快照/追赶、激活授予、Live、Degraded 和恢复代次 |
| Commit 强制 Origin/RequestId 来自客户端请求 | 增加 PlayerIntent / Simulation / System / Recovery 的明确来源类型 |
| 整世界 ExpectedRevision 精确相等 | 支持对象 generation 与读集版本；不同区域可并发，冲突仍主机裁决 |
| 请求计数跟随传输连接 | 与逻辑成员操作账本分离；重连换连接，不重做已执行操作 |
| 固定 512 条内存日志 | 条数+字节+时间+租约管理的不可变分段日志，不能无限保留 |
| 内存 WorldImage | 面向真实城市的流式不可变 CheckpointHandle，载入和内容校验分开 |
| 引用世界原子交换 | 游戏适配须证明投影原子发布或采用隔离后完整重载 |
| PeerLiveness 单一健康指标 | 网络、Host 进展、Client 应用进展、加载进展各自监测 |
| 帧内 SHA-256 | 保留完整性用途；加真实对端认证，不能把摘要当 MAC |

这些变化不得直接重解释旧协议；先并存 v1 测试与 v2 类型，完成纵切片后淘汰仅参考域的临时实现。旧测试用来锁住已证明的性质，不作为新功能证明。

## 10. 开发与发布判据

完整性由“需求—规范—工作包—验收证据”闭环定义，不由文档字数或 DLL 数量定义。路线见实施文档。运行时隔离、自然模拟闭包、原生检查点和真实弱网络均为发布前硬门槛；不能只因内核测试通过就发玩家版本。

并行开发围绕已冻结的 DTO/契约进行，不围绕共享游戏全局对象并发修改。新功能默认关闭，先模型测试，再真实游戏回调，再多进程与多机；观察补丁不能作为真实隔离成功证据。所有数值性能预算均为待测验收目标，不能写成已取得的性能数据。
