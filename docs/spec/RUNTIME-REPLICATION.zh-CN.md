# 游戏运行时、权威模拟与结果复制

规范版本：2.0-design。关联需求：F-AUTH-01、F-AUTH-02、F-STATE-01、F-STATE-02、F-REC-01、F-MOD-01。以下为待实现契约，当前 CS1 项目仍只包含加载探针。

## 1. 可行性先验证，不靠协议掩盖引擎问题

生产编译边界保持 net35；现代 .NET 用于工具和测试。真实游戏版本的程序集、bundled Mono、Unity、DLC、Harmony 和补丁目标签名必须记录并逐一验证。标准 Mono 上运行 net35 程序不是游戏验证。

只有存在完整的客户端写屏障、游戏状态投影和安全保存切面，才允许实时多人。不能仅拦截 SimulationManager.FixedUpdate 就宣称客户端已无权威模拟：工具、其他扩展、异步完成回调或独立 Manager 入口也可能写状态。具体入口要通过目标游戏版本的合法本地程序集检查和运行探针确认，而非从历史 CSM 源码假定永久不变。[S-CSM][S-HARMONY]

G0/G1 探针要记录加载、卸载、主线程与模拟线程的真实执行关系。识别方法存在不等于补丁安全；观察回调不等于已经阻止原方法。Patch 安装部分失败必须撤销本 Mod 已安装部分并不开房，不影响其他 Mod 的补丁。

## 2. 线程与生命周期

网络工作者只做解码、身份验证、配额和不可变 DTO 投递。后台工作者只处理已冻结字节、磁盘、摘要、压缩和传输；不得遍历实时游戏对象。UI 主线程控制可见组件，模拟 owner-thread 控制城市写入；两者通过有界 dispatcher 交接。

每个投递项包含 World/Epoch/LoadGeneration；换图和卸载撤销代次，旧任务在入队和执行两处被拒绝。Unity 对象销毁后，不依靠弱引用恰好为空来判断任务过期。任何游戏锁都不覆盖 socket 等待、下载、异步保存完成等待或其他玩家确认。

角色状态至少区分 SinglePlayer、HostPreparing、HostLive、ClientLoading、ClientReplicaLive、ClientRecovering、WorldFenced、Unloading。未完成角色初始化时保持安全写屏障。联机结束后恢复原单机行为，但损坏/部分安装的 Client 世界不能直接解锁为可信单机城市；默认卸载或从有效检查点重新加载。

## 3. 客户端模拟隔离

隔离分三层，而不是一个全局 Ignore 布尔值。

第一层是输入：所有受支持的持久工具操作先变成 Intent，预览仅画幽灵几何，不提前扣款、分配正式对象或保存。未支持工具的持久提交按钮/热键被禁用；不能仅隐藏按钮而保留另一入口可写。

第二层是世界写入入口：对会改变权威状态的目标 Manager/扩展入口建立角色感知守卫。Client 只有持有当前 `ApplyScope(BatchId, DomainSet, LoadGeneration)` 才允许执行经验证的结果安装；其余持久写入被拒绝并记录。读取、渲染缓存重建和明确的纯表现工作可继续。

第三层是模拟工作：客户端不自主推进经济、生长、居民/车辆任务、运输决策等权威规则；必要的动画和 UI 调度不能因此停摆。Manager 的 simulation、更新和渲染职责若混在一个入口，必须拆清调用路径或采用明确的投影更新器，不能粗暴跳过整个引擎循环。

ApplyScope 是每次调用拥有、支持嵌套且严格恢复的作用域；它不是让第三方任意游戏逻辑在 scope 内运行的授权。嵌套调用超出预期 DomainSet 视为覆盖缺口。Harmony 清理可使用 Finalizer，但必须保留原始异常，不以吞异常伪装应用成功；没有可证明补偿时转入恢复。[S-HARMONY]

## 4. 领域覆盖与相互依赖

下表是最低检查清单，不是全部 CS1 私有字段的枚举；每个版本的适配器还须维护实际字段/方法与测试映射。

| 领域 | Host 权威事实 | Client 投影及派生工作 | 依赖与特别风险 |
| --- | --- | --- | --- |
| 世界/时间/规则 | 世界身份、游戏 tick、速度、暂停、规则与解锁 | 时间显示、允许的效果进度 | 真实暂停不等于断线，不能误触发超时 |
| 地形/水系 | 高度、地形修改与影响游戏规则的水状态 | 地表/水面可视资源重建 | 拓扑、建筑高度、洪水与费用关联 |
| 道路/网络 | 节点、路段、连接、车道、引用、Prefab、generation | 受控分配与索引/网格更新 | 分区块、道路设施、费用、其他道路 Mod |
| 建筑 | 创建/升级/迁移/删除、地块归属、容量、状态与库存 | 网格、可见性、信息面板 | 道路、分区、服务、资源、居民引用 |
| 分区/行政区 | 格子、边界、地区/园区政策与规则 | 区域纹理和 UI | 建筑生长、税率、道路生成分区块 |
| 经济/资源 | 资金、费用、预算、税率、生产消费、服务需求 | 数值显示及派生图表 | 绝对值与事件费用一致，不能二次扣款 |
| 居民/家庭 | 生命周期、家庭/住宅/工作关联、任务与物资需求 | 选中查询、经审核的代理表现 | 不得让 Client 自主决策并反向修改经济 |
| 车辆/寻路 | 生命周期、任务、路径引用、载荷、游戏决策相关位置 | 可见位置/转向插值、只读路径可视化 | 寻路异步完成、ID 重用、任务产生经济影响 |
| 公交/货运 | 线路、站点、车辆归属、调度及乘客/货物关系 | 路线面板和表现更新 | 关联实体跨域，不按 GUI 操作独立重演 |
| 灾害/事件/DLC | 事件生命周期及所有规则副作用 | 已支持效果和 UI | 每个 DLC 单独能力门槛，不支持则禁用/拒绝 |
| 资产/Mod 状态 | 稳定内容身份、适配的扩展数据和配置 | 本地资源绑定 | 相同显示名不够；加载回调可能额外写世界 |

实体引用图决定故障恢复粒度。道路拓扑损坏可能影响建筑、分区、车辆和路径，不能只覆盖一个 segment 字段并宣布恢复。首版默认完整 Client 检查点重载；只有适配器声明并测试了封闭域替换，才允许局部恢复。

## 5. 权威批次与自然模拟

新增 `AuthorityBatch` 的 OriginKind：PlayerIntent、Simulation、System。恢复安装不是新的游戏输入；它在 Client 使用独立应用上下文，不伪造玩家 RequestId。源请求身份只对 PlayerIntent 必填，不能把自然模拟全部归到某个伪造玩家。

Host 玩家和 Client 玩家都先经过命令权限、对象 generation、读集版本、范围、资源/规则和配额校验。不同区域操作可串行裁决后均成功；共享对象冲突按读集版本拒绝并返回最新必要状态。不能对所有操作要求客户端全世界 Revision 永远等于 Host 最新头，否则实时自然模拟会让输入持续过期。

自然模拟接入采用安全边界上的捕获窗口：标记开始状态版本，观察完整领域闭包内的新增/修改/删除，捕获已经由 Host 算出的结果，规范化并封装批次。对其随机结果、异步结果和规则副作用传最终事实，不让 Client 重跑决策代码。未知写入进入诊断并停止该能力，不能作为“后台游戏改动所以忽略”。

异步寻路等工作者不得被假设服从一个模拟线程锁。由适配器证明 worker 的输入不可变、完成结果只在可控提交点消费；若工作者直接修改将被采样的数据，要使用引擎已有同步边界或记录并版本化相关写入。不能仅在模拟线程中拿到数组引用就称为一致快照。

每个批次有前置根、后置根、修改实体与依赖、大小/实体数限制。超大工具操作需事前规划和限制；拆成多个批次时每个中间状态必须有效，或整个批次组在一个不可分割发布边界对外可见。禁止静默截断结果。自然模拟无法在容量限制内封装时，是支持规模/捕获能力不足，应安全停房并报告，不允许丢弃持久变化保持帧率。

## 6. 双阶段状态：规范化镜像与游戏投影

Forge 维护显式版本的规范化镜像，便于连续应用、脏集与状态根。镜像不是另一个独立模拟器。镜像与 CS1 实际对象同时属于一致性边界：仅镜像哈希正确，而游戏里道路没建出来，不算成功。

Client 流程：完整收齐批次 → 验证 Schema/边界/读集/引用/generation → 在候选镜像中应用并核对预期根 → 生成游戏投影操作计划 → 在许可的游戏线程与 scope 中安装 → 更新派生缓存 → 校验所需真实对象 → 发布 AppliedRevision 和 UI 通知。

应用前可以分帧做纯计算和资源准备。进入不可逆游戏修改阶段后，不能任意 yield 暴露半份拓扑给渲染或其他系统。能通过受控读屏障/双缓冲分帧发布的适配器需单独证明；否则限制批次大小，在允许的安全窗口内完成，失败则遮蔽相关画面、禁用编辑并完整恢复。

游戏 API 创建对象时会触发副作用，不能简单调用 CreateBuilding 后再覆盖字段就视为绝对结果安装。需要针对费用、AI 初始化、关联分配、粒子效果、Mod 回调逐项决定禁止、重建或记录。宿主 API 没有已验证事务时，不承诺跨 Manager 回滚。

## 7. 实体 ID、引用和删除

网络身份为 `(DomainId, EntityId:u64, Generation:u32)`，Prefab 使用内容集中的稳定 key。Host 原生 ushort/uint 索引不能直接作为永久网络身份。Client 维护双向映射并验证唯一性；重复创建必须得到幂等结果或错误，不重新分配同一实体。

对象安装的基本顺序是预留受支持本地句柄 → 安装无环基础数据 → 解析允许的循环引用 → 校验引用闭包 → 受控更新索引和可见性。道路复杂对象的真实步骤由适配器锁定版本实现，而不是复制旧 ArrayHandler 的混合分配列表。

删除结果含 tombstone 和 generation。对旧代次的迟到表现更新直接丢弃；对旧代次的持久修改明确拒绝。tombstone 可在所有有效基线/成员均不再引用旧代次后回收，或通过新检查点和 Epoch 边界压缩，不能仅按墙钟过期而允许 ABA 身份混淆。

传输/资产无映射时不降级成本地随机 ID 或同名 Prefab。缺少必需资产在下载城市前拒绝；运行中资源被替换则取消能力/会话，不悄悄使用其他模型。

## 8. 状态根与不同步定位

规范化编码明确字段顺序、整数位宽、字节序、字符串编码、有效浮点策略和 Schema。禁止使用进程随机 GetHashCode。游戏事实保留其必要精度；不为消除哈希差异随意量化规则相关浮点。表现位置可独立量化，不能混入相同的持久根。

每个领域维护版本化分区根；根树节点包含 Domain、Schema、Partition 和子版本。所有用于 Root(R) 的域根必须对应同一个发布边界，不能把不同时间扫描得到的各部分拼成一个伪一致根。增量脏标识自身需要覆盖测试和周期审计，否则漏标写入会让哈希“稳定但错误”。

正在变化的游戏对象不能跨数帧扫描后标为一个旧 Revision；应读取该 Revision 冻结的镜像/页，或者明确标记为不可比较样本。真正游戏投影的周期读回只在可比较的安全点执行，记录其与镜像一致性，不用镜像自己验证自己代替适配检验。

定位链：全局根 → 领域根 → 分区根 → 实体记录摘要 → 最近相关操作与投影事件。只传差异需要的有界摘要，默认不上传完整城市。部分域修复前先证明依赖闭包，否则完整 Client 重载。Host 根异常按房间级故障处理。

## 9. Mod 与游戏版本兼容

支持目录由维护者控制并绑定游戏 build、Mod 二进制/配置、适配器 Schema 和操作测试矩阵。纯 UI/相机可在审核后本地独立；工具类 Mod 必须映射到 Intent 或完整结果计划；模拟类 Mod 需要覆盖 Host 结果与 Client 禁用/投影语义；共享内容通过稳定资产 key 校验。

“同样安装 TM:PE/81 Tiles”不能替代适配；“HostOnly”也不意味着该 Mod 的结果客户端自动看得懂。运行中不热替换 Schema/游戏 Mod 集合；变更须关闭房间、保存有效检查点并重新协商。未知方法签名或新游戏补丁不使用模糊反射继续执行。

Harmony 安装/卸载只操作 Forge 自己的 Harmony ID。修复某个清理函数不得调用全局 UnpatchAll 清除其他 Mod 补丁。补丁排序、原方法抛错、第三方 Postfix/Finalizer 抛错和重复加载必须纳入实际测试。[S-HARMONY]

## 10. 恢复与发布门槛

Client 部分失败后的信任状态为“尚未确认”，不是自动回退到前一 Revision。隔离本 Client，保留首次错误，撤销编辑与旧 LoadGeneration；从可信检查点重新加载，完成补日志和独立激活。整个过程中 Host 和其他正常 Client 不等待。

Host 部分失败、未知持久写入或提交日志不再覆盖当前状态时，停止世界写入和新快照发布。仅从先前有效检查点恢复，新 Epoch 使全部旧请求、连接和屏障失效。原生崩溃/游戏进程退出不在托管异常恢复承诺中。

发布需要覆盖实际持续模拟、暂停/加速、自然生长、交通与经济反馈、并行加入、道路并发、保存/加载与卸载。详见 [验收](ACCEPTANCE.zh-CN.md)。[来源索引](SOURCES.zh-CN.md) 区分已有证据与工程设计。
