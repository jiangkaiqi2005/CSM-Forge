# 可执行验收规范

规范版本：2.0-design。这里定义将来必须通过的验收，不报告已经执行的 v2 测试。当前 M0 的 68 项回归只证明其既有参考域性质；不得把这些测试改名为真实并行加入、认证或实时城市测试。

## 1. 证据层级

E0 是文档/静态契约检查；E1 是直接引用生产内核的确定性状态机与虚拟链路测试；E2 是实际原生传输/磁盘故障/多个进程；E3 是真实 CS1 进程和真实游戏程序集；E4 是独立电脑、弱网络、持续运行和发行候选。

较低层通过不能替代较高层。测试替身只允许在游戏、存储、网络、时间等外部边界；生产逻辑不能在测试中被改写成更容易通过的算法。模型失败用固定 seed 和最短事件链复现，修复前先保留失败回归。

## 2. 需求验收案例

### AT-01 主机唯一裁决

需求 F-AUTH-01；工作包 WP-01/WP-07。Host 本地与两个 Client 对同一/不同对象发操作，插入重复、旧读集、无权限输入。Oracle：只有 Host 增加 Revision，同一操作最多执行一次；不同区域读集不冲突时可都成功；客户端没有正式本地预执行。E1 与 E3 均需。

### AT-02 自然模拟变化也可追赶

需求 F-AUTH-02；工作包 WP-08。不做任何玩家点击，持续推进经济、建筑生长、居民/车辆任务和运输；另一 Client 从旧检查点加入。Oracle：只依赖完整结果流即可达到同一发布边界的游戏投影，不能重新执行 Host 的自然规则来补遗漏；未跟踪写入可被检测。E1/E3/E4，实时产品的阻断项。

### AT-03 连续批次和世代边界

需求 F-STATE-01；工作包 WP-02。逐字节损坏、全部截断位置、超长字段、缺 begin/part/end、重复冲突、错误 Epoch/generation、重连后的半批次。Oracle：未完整验证不触碰世界，不确认 Applied；旧代次不污染新状态；失败资源有界。E1/E2。

### AT-04 客户端模拟隔离

需求 F-STATE-02；工作包 WP-06。无 Host 消息时尝试所有受支持工具、快捷键、自然规则入口和已启用 Mod 回调；运行暂停/加速/卸载。Oracle：无自主持久变化，相机、UI、预览、渲染和必要调度仍工作；镜像和真实投影均监测。E3，不能由探针“发现方法存在”代替。

### AT-05 运行中两人并行加入

需求 F-JOIN-01；工作包 WP-04/WP-10。Host+一个已入房 Client 持续运行与编辑，C/D 同时开始加入；明确记录两人的下载/加载/追赶阶段重叠。Oracle：C 可先 Live 而 D 仍在加载；正常玩家不停等；每人最终在自己屏障上语义根一致。E1/E2/E3/E4。只有下载线程重叠、游戏载入仍全局串行，不合格。

### AT-06 独立取消与资源释放

需求 F-JOIN-02；工作包 WP-04。C/D 共享快照，在下载、校验、加载和激活前分别取消其中一个，覆盖与完成回调的两种先后顺序。Oracle：另一人仍成功，Host 不暂停，公共文件在仍有引用时存在，最后租约释放后可回收。连续 100 次尝试用于 E1/E2；E3 至少 20 次。

### AT-07 基线与实时订阅无空窗

需求 F-JOIN-03；工作包 WP-03/WP-04。在取得 B、pin 日志、发 offer、切历史/实时流、回收日志之间的每个交错点插入 Host Commit。Oracle：B 之后每个有效结果恰好被连续应用一次或明确恢复，不允许静默漏一个结果。测试使用可记录提交集合的模型，而不只比较最终一个整数值。E1/E2，再做 E3。

### AT-08 固定历史屏障不追逐当前头

需求 F-JOIN-04；工作包 WP-04。Barrier H 发出后 Host 持续提交，再延迟 Ack 和 Grant；人为让 CONTROL 比 STATE 先到、或 client 收到 Grant 但游戏还未应用 A。Oracle：有效 H 的 Ack 不因主机变到更高 Revision 被误拒；A 发布前不开放编辑；过期/撤销的授权不能生效。E1/E2/E3。

### AT-09 不同故障采用不同恢复

需求 F-REC-01；工作包 WP-04/WP-09。注入日志内缺口、日志外缺口、镜像不同步和真实投影部分失败。Oracle：前者补日志，后者按可信闭包完整重载，不能单纯修改 Revision 或 reset Ignore；恢复后完成新的屏障与激活。E1/E3。

### AT-10 重连与旧回调

需求 F-REC-02；工作包 WP-04/WP-05。在旧连接关闭/新连接成功、旧加载结束/新加载开始、换图/旧快照完成之间排列事件。Oracle：新绑定和新 LoadGeneration 才能生效；旧事件不关闭新连接、不释放新租约、不安装旧世界。E1/E2/E3。

### AT-11 结果未知不盲重试

需求 F-REC-03；工作包 WP-01。Host 执行后丢失 Receipt，再断线/重连，另测回执淘汰、成员代次复用、检查点回滚。Oracle：已执行操作不再次扣款/建造；Expired/Unknown 被明确显示，不能自动生成新操作重复执行。E1/E3。

### AT-12 检查点崩溃矩阵

需求 F-SAVE-01；工作包 WP-03/WP-09。在每个写文件、刷盘、写 manifest、sealed 发布和 latest 替换步骤前后注入故障或终止独立进程。Oracle：恢复只选完整校验的检查点；`.crp` 与元数据属于同一 B；原始用户存档未改；新 Epoch 拒绝旧包。E2/E3，断电持久语义须另有平台证据。

### AT-13 最小隔离范围

需求 F-FAIL-01；工作包 WP-04/WP-10。分别注入客户端损坏、无效远端报文和 Host 部分写入。Oracle：前两者不停止其他人的游戏；Host 污染时立即停止新的权威修改与新快照，绝不广播污染快照“修复”客户端。E1/E3/E4。

### AT-14 资源、公平和慢端

需求 F-LOAD-01；工作包 WP-03/WP-05。设置一个下载极慢/应用能力低于 Host 生成速率的 Client，另外一个正常加入，已在线玩家持续操作。压满状态队列、快照缓存、日志租约与磁盘预算。Oracle：资源不超过批准边界，无饥饿式无限等待；正常玩家可继续；慢端有明确拒绝/恢复/断开结果。E1/E2/E4。

### AT-15 独立健康信号

需求 F-LIVE-01；工作包 WP-04。覆盖 Host 明确暂停、网络通但模拟卡死、载入线程卡住但 IO 有心跳、反向系统时间跳变、长延迟包。Oracle：正常暂停不误判；真正停滞不会被心跳无限掩盖；超时只用单调时间；恢复健康不自动绕过 Ready。E1/E3。

### AT-16 身份与授权

需求 F-NET-01；工作包 WP-02/WP-05。错主机密钥、过期/复用票据、伪造 MemberId、错误连接绑定、未认证大请求、观众写入、内容清单少页/冲突。Oracle：解码有界，城市数据未泄露给未授权者，世界入口未执行。E1/E2，原生身份通道绑定需独立审查，不能仅测 SHA 正确。

### AT-17 游戏/Mod 兼容矩阵

需求 F-MOD-01；工作包 WP-11。相同名字不同程序集/配置、未知额外模拟 Mod、版本改变、缺资产、运行时补丁变化。Oracle：加入前准确拒绝/报告；仅审核过的本地功能可不同；每个宣称兼容操作均有真实游戏成功/失败/恢复证据。E1/E3。

### AT-18 首次分叉诊断

需求 F-OBS-01；工作包 WP-12。制造一个有固定种子的首次分叉并继续注入大量后续错误。Oracle：第一有效分叉仍保留，能定位 Revision/Domain/Partition 与关联操作；不可比较样本不误标 desync；诊断包不含票据、密钥、完整存档和私人路径。E1/E3。

### AT-19 可取消且诚实的 UI

需求 F-UX-01；工作包 WP-10。开房失败、下载完成但仍在加载、追赶、结果未知、重载失败、退出/再次加入。Oracle：进度与实际阶段一致，所有长阶段可取消；本地正式编辑只在有效 Live 开放；不让“100% 下载”冒充可游玩，不弹全房阻塞提示等待单个 Client。E3/E4。

### AT-20 持续游玩与发行

需求 F-REL-01；工作包 WP-12。四人支持配置下连续 24 小时运行，包含操作/自然模拟、至少 20 轮并行加入或重连、保存/重载、一次单客户端故障恢复和可控网络劣化。Oracle：无未解释的持久状态分叉、无无界资源增长，所有错误按矩阵归类，有发行文件哈希与完整证据。此测试尚未执行。

## 3. 网络与城市测试矩阵

网络测试按 RTT 0/50/150/300 ms、丢包 0/1/3/5%、抖动、1 秒/10 秒/30 秒断网、不同上下行带宽、重复与乱序组合。不是全部笛卡尔积强制穷举：先边界与成对覆盖，再根据故障高风险补组合，并公布跑过的单元格；未跑项不能标绿。

覆盖纯直连、NAT 后直连、需要中继、信令不可用、中继中断；不声称公网通信一定能穿透任意网络。压力记录实际生成/消费速率、队列峰值与恢复时间。

城市夹具分为空图、小城、交通/居民密集城、接近公布支持上限的城市；夹具不能把私人用户城市提交公开仓库。记录人口只是描述，真正规模还包括网络实体、活跃代理、每秒持久变更、快照/日志字节和 Mod/DLC 组合。支持上限由测量决定，不先编造“支持百万居民”。

## 4. 性能验收方法

`budgets.json` 中时间/容量是提议阈值，不是已证明性能。对同一硬件/城市/游戏速度，比较单机基线、Host 稳态、双人稳态、两人同时加入和单 Client 恢复。预热后至少采样 30 分钟稳态，长时间项另做 24 小时。

记录 p50/p95/p99、最大停顿、CPU/内存/GC/磁盘/带宽与样本数，不只给平均 FPS。稳态 tick 额外开销 p99 2 ms、游戏发布窗口 p99 8 ms、快照安全点 p99 250 ms、并行加入对活跃流 RTT p95 额外 50 ms 为初始目标；达不到应优化或如实缩小支持配置，不能改写报告假装通过。

快照安全点统计不包括等待远端下载/加载；如果存在这种等待即违反架构。超过窗口的不可逆游戏操作不能直接线程中止来“保证预算”；需改适配器或停止开放该操作。额外内存与城市基线分开测量，磁盘缓存不算作免费无限容量。

## 5. 证据与升级门槛

每条证据保存精确 Commit、协议/Schema、硬件、游戏/Mod 指纹、夹具身份、seed、故障时序、预期/实际、退出码和测试层级。CI artifact 的 green 只能覆盖该 artifact 记录的层级；E3/E4 没有记录就保持未测。

每个工作包先有契约测试与故障测试再接游戏。E1 可并行开发，E2/E3 各有阻断依赖；生产发行必须 AT-01..AT-20 在声明支持配置内通过。旧 68 项 M0 回归继续运行，允许明确替换过时接口测试，但不能删除关键安全性质来消除红灯。

文档检查器只验证需求覆盖、路径/链接、工作包依赖无环和预算关系。它不能证明协议正确，更不能证明原生或游戏功能已实现。
