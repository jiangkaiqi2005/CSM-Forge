# MVP 与实施顺序

## 本次阶段：架构落地与一致性内核 M0

目标不是先拼出一个能发送道路命令的窗口，而是建立在失败条件下也可检验的权威复制底座。已完成参考世界上的主机裁决、结果复制、缺口/快照恢复、协议边界、分片存储、兼容策略、时间与诊断算法，并接入公开 CI。另已创建仅做观察的 ICities 探针源码。

**M0 是开发者内核 MVP，不是可游玩的 Cities 多人 MVP。** 当前没有真实传输、房间服务或城市状态适配；不能把整数槽用例写成“已经同步游戏税率”。

## 首个可游玩 MVP：M1 暂停城市的双人协作编辑

平台先限定 Windows x64、相同 CS1 游戏版本和已核对的 DLC/内容集、无未适配的第三方模拟 Mod。房间最多两名玩家。城市在共享编辑期间保持暂停，不开放自然生长、交通与经济的实时推进。

垂直切片范围：主机开房 → 客户端加入同一快照 → 双方经主机裁决修改一个真实原版参数 → 创建/删除一类基础直道路 → 所有相关拓扑、费用和分区块保持一致 → 掉线后禁止编辑 → 重新加入/快照恢复 → 主机保存并重载后结果一致。

不支持的工具必须禁用并解释原因。首版不包含曲线/升级/复杂交叉口/任意批量工具、公共房间浏览、Host 迁移、跨版本加入和未审核 Mod。道路中途失败不能靠“随后再同步一次”掩盖，必须进入已定义的隔离与恢复路径。

局域网阶段可先验证传输和游戏语义；面向普通玩家的互联网开房体验还必须补齐认证、邀请码发现、直连/中继及端到端验收。仅可局域网运行的构建不得宣称已经实现普遍的开房—加入体验。

## 下一批实现的确定顺序

1. **G0/G1 运行时可行性验证。** 用合法本机游戏引用编译探针，核实 bundled Mono，再建立 owner-thread 调度与客户端模拟/持久写入隔离。通过实际相机/UI/预览/渲染/读档测试才添加更多功能。
2. **真实传输与会话协调。** 实现窄 GNS 适配及 ABI smoke test、固定 Bootstrap、认证连接实例、兼容清单采集和准入。把超时、取消、快照、补日志与 Ready 算法串成一个实际生命周期。
3. **原版参数垂直切片。** 选一个具有清晰最终值和副作用边界的真实原版参数。Host 本地与 Client 操作走同一路径；只读/加载/断线时无法本地抢先修改。
4. **基础道路结果适配。** 完成逻辑 ID + generation 映射、实体/引用闭包、费用与缓存处理；证明不是客户端重跑整个工具入口。加入并发、过期引用、删除后重用和部分失败回归。
5. **原生检查点与实际恢复。** 一致保存切面、磁盘发布、元数据/内容校验、安全加载、有限追赶与回退；检查点后操作丢失范围明确展示。
6. **M1 双机验收与最小 UI。** 跑 docs/TESTING.zh-CN.md 的阻断性矩阵，确认无误后再产出玩家安装包和开房/加入界面。

顺序不要求每次都重开架构讨论；按照依赖实现并提交证据。遇到不可满足的游戏引擎约束时记录可复现事实并修改对应 ADR，而不是静默绕过不变量。

## M2：实时共同经营城市

只有持续模拟涉及的经济、资源、建筑生长、居民、车辆、公共交通、寻路相关事实及事件已纳入权威闭包后，才允许解除暂停。主机自然模拟更新也需要进入明确的结果/状态发布边界；表现层可以插值，持久状态不能由客户端猜测。

这一阶段才建立域级增量根、状态优先级、表现兴趣管理、大城市压力测试、跨平台验证和更广的操作覆盖。为带宽做近似压缩时必须区分可近似表现和不可近似的游戏事实。

## M3：兼容生态与易用发行

为特定 Mod/版本编写能力适配器和自动化/实机测试，建立可审计的支持目录；加入诊断导出、恢复 UI、房间服务运维与可升级协议。未知模拟插件默认拒绝；相同 Mod 列表本身不是支持证据。

## 明确的停止条件

无法安全隔离客户端模拟、无法捕获道路操作的完整闭包、快照根与提交 Revision 不可建立一致关系、或者实际旧 Mono 不支持选择的原生边界时，相应功能不得对玩家启用。收缩已支持范围比带着已知漂移继续开放更多工具更符合项目目标。
