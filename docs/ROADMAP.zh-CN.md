# 完整实施路线与并行开发计划

路线版本：2.0-design。基线 `225fd25151fb6ec0a8dae3e95ca2945fb4270462`。本次优先完成技术文档与实施契约；以下 WP-01..WP-12 均为 planned，未把文档更新算作游戏功能完成。

## 1. 目标修订

正式目标是可持续运行的多人共同经营、游戏进行中并行加入、单客户端独立恢复和清晰的异常诊断。首发目标四人（含 Host），至少两名玩家并行加入。旧的“暂停城市双人编辑”只保留为内部可行性关卡，不再称为最终可游玩产品 MVP。

原 M0 已有参考世界内核、v1 帧、有限日志/回执、分片/兼容策略和 68 项回归；没有真实传输、GNS 认证、并行加入协调器、客户端模拟隔离、自然模拟结果适配、原生检查点或正式 UI。完整文档是下一阶段实现入口，不改变这个事实。

## 2. 里程碑与退出条件

| 里程碑 | 实际交付 | 退出条件 |
| --- | --- | --- |

| M0.5 并行会话实验室 | 持续提交参考世界，多个独立 Client 状态机、固定屏障、有限租约 | E1 故障矩阵与真实进程 E2 通过，不称游戏多人 |

| M1 内部协作编辑 | 暂停城市、真实工具闭包、检查点和重连 | 核实实际游戏结果与恢复；只是内部关卡 |
| M2 实时多人 Alpha | 必需自然模拟闭包、运行中两人并行加入、正常玩家继续 | AT-01..AT-19 在受限支持配置下通过 |
| R1 玩家发行候选 | 四人、联网易用性、完整诊断/恢复、支持目录和包 | AT-20 长跑及全部阻断测试、文档和发行产物一致 |

阶段由证据推进，不按一个未经验证的日期倒排删减安全性。遇到 G1 或完整闭包问题，应修适配器/收缩暂时范围并记录 ADR，不把问题藏进周期性强制重同步。

```text

                    ├─ WP-03 检查点/日志 ─┐
                    └─────────────────────┴─ WP-04 并行加入
WP-06 CS1 探针/隔离 ─── WP-07 参数/道路 ─── WP-08 自然模拟
          │                    └─ WP-09 原生保存/加载（还依赖 WP-03）

WP-04/05/07/08/09 ─── WP-10 实时集成与 UI
WP-10/11 ──────────── WP-12 长跑、诊断与发行
```

箭头是生产合入依赖；编写测试、设计夹具和探针可提前并行，不等于用测试替身绕开依赖。精确依赖以 [spec-index.json](spec/spec-index.json) 为机器可检查索引，以下包定义为语义依据。

## WP-01 权威批次、逻辑成员与核心契约

状态 planned；lane Core；依赖无。交付 v2 身份 DTO、逻辑成员操作账本、PlayerIntent/Simulation/System 来源、域/对象 generation 与读集版本、Host 发布边界、历史根句柄和状态机错误类型。

必须改掉“所有 Commit 必须有客户端 RequestId”和“所有实时 Intent 要全世界 Revision 完全相等”的限制。保留 v1 类型/测试直到迁移明确。添加重复/冲突/回执淘汰/成员复用/Host 本地入口测试，明确跨崩溃承诺边界。关联 AT-01、AT-11。

## WP-02 固定 Bootstrap 与协议 v2

状态 planned；lane Protocol；依赖 WP-01。交付固定消息表、88-byte 会话帧、受限 Bootstrap/清单分页、批次分片与整体校验、消息方向/阶段检查、golden vectors 和独立 codec 互测。

冻结 Bootstrap 字节布局前联调 WP-05 的实际认证证据；不能假设不存在的传输 API。测试畸形、截断、过长、缺 part、未知 schema、连接绑定错误和跨 lane 乱序。v1/v2 不能静默混用。关联 AT-03、AT-16。

## WP-03 不可变检查点目录与有界提交存储

状态 planned；lane Storage；依赖 WP-01。交付流式 CheckpointHandle、SnapshotCatalog、single-flight、独立流游标、引用计数/租约、历史根、按字节/时间/租约回收的 CommitStore 和崩溃安全发布抽象。

使用参考领域和独立进程先验证文件流程，不假装已经生成可用 .crp。涵盖共享文件一人取消、租约到期、日志淘汰、低磁盘、半份 manifest、latest 指针损坏和容量峰值。关联 AT-07、AT-12、AT-14。

## WP-04 并行加入与独立恢复协调器

状态 planned；lane Sessions；依赖 WP-01、WP-02、WP-03。交付 per-member JoinContext、代次、原子 B+日志订阅、历史/实时有序流、固定 H/root 校验、A 激活、单调时间健康判断、取消/重连/有限恢复。

先接生产核心与虚拟传输形成 M0.5，不在这个包等待真实游戏接口。必须实现至少两个重叠流程，并验证一个慢/取消时另一个成功。为旧 CompleteJoin equality 增加反例，不仅把等号删掉。关联 AT-05..AT-10、AT-13、AT-15。

## WP-05 GNS、认证、联网服务与调度

状态 planned；lane Transport；依赖 WP-02。交付目标平台原生 ABI smoke test、可靠/不可靠 lane、持续网络轮询、连接代次、安全票据与通道绑定、房间级公平带宽和字节背压、真实网络故障实验。

先证明独立 GNS 的受信身份/证书能力适合部署；不成立则阻断合入并修订 ADR，不能只实现加密后假称认证完成。信令/中继实现需要单独部署配置、密钥与限流审查，但与游戏权威保持分离；不替换 Steam API。覆盖 NAT/中继/证书拒绝/原生回调晚到。关联 AT-10、AT-14、AT-16。

## WP-06 真实 CS1 生命周期与模拟隔离

状态 planned；lane Runtime；依赖无。可与 WP-01 同时开始。交付合法游戏 DLL 构建、游戏内 probe 证据、真实线程模型、角色生命周期、LoadGeneration、补丁签名检查、客户端输入/写入口/模拟隔离和安全卸载。

不以 net8 或标准 Mono 成功代替游戏。先证明相机/UI/预览/渲染正常，Client 没有自主持久写入；验证其他补丁异常下作用域恢复。记录不能隔离的具体 Manager/线程，决定适配而非泛化跳过 FixedUpdate。关联 AT-04。

## WP-07 真实参数与基础道路完整结果

状态 planned；lane Domains；依赖 WP-01、WP-06。交付一个真实原版参数，以及一类基础道路创建/删除的结果 DTO、实体 ID/generation 映射、引用闭包、费用和派生缓存处理，Host 本地与 Client 同一路径。

先在暂停城市完成 M1 内部纵切片。覆盖并发、过期对象、删除/重用、缺资产、嵌套副作用和部分应用故障。不得靠远端重跑整个工具或复制原版 ArrayHandler 实现。关联 AT-01、AT-09。

## WP-08 持续模拟与完整必要领域复制

状态 planned；lane Simulation；依赖 WP-07。交付运行时规范领域覆盖表中的实时产品必要闭包：经济资源、建筑生长、居民/家庭、车辆/路径/运输事实、时间与规则，以及已支持 DLC 的必要事件。

各域内部可以并行实现，但先冻结跨域引用和原子批次边界；未覆盖依赖不得提前开启该域实时功能。每域都需要输入隔离、Host 捕获、绝对结果、Client 投影、根和保存/恢复适配，不只加一个消息类。缺少任一必要域时保留内部实验状态，不能把持续模拟留给 Client 自行运行。关联 AT-02、AT-04。

## WP-09 原生保存切面、加载和检查点恢复

状态 planned；lane GameStorage；依赖 WP-03、WP-06、WP-07。先从暂停纵切片开始，随后与 WP-08 完成实时切面集成。交付原生 `.crp` 与 Forge 元数据/映射一致的 B、冻结/后台工作的真实边界、不可变文件发布、加载语义验证和旧代次回调清理。

验证是否能短安全点生成快照；不能做到时明确缓存快照覆盖与长保存限制，不把下载等待纳入暂停。注入每个发布步骤的终止、磁盘满、加载失败和重启。关联 AT-09、AT-12。

## WP-10 实时集成、并行加入与玩家 UI

状态 planned；lane Integration；依赖 WP-04、WP-05、WP-07、WP-08、WP-09。把参考协调器接实际世界、传输和检查点；交付四人席位管理、至少双加入重叠、有限重载、网络/模拟/加载健康显示、操作回执和真正可取消的加入流程。

Host+一名在线 Client 持续游玩时 C/D 加入，C 可先 Live、D 可取消/重连，任何一个都不阻断其他人；支持城市暂停与加速而不误判。未支持工具明确禁用。关联 AT-05、AT-13、AT-19。

## WP-11 兼容采集与支持目录

状态 planned；lane Compatibility；依赖 WP-02、WP-06。交付游戏/DLC/资产/Mod/配置实际指纹采集、支持目录版本、分类证据和入房前差异报告。先原版与必需补丁，再逐项工具/模拟 Mod，未知保持拒绝。

能力必须绑定到具体版本与操作测试，不能通过 Host 当前 mod 列表自动全放行。涵盖额外有害逻辑、同名不同程序集、缺资产和运行中变更。关联 AT-17。

## WP-12 故障实验室、诊断、长期运行与发行

状态 planned；lane Quality；依赖 WP-10、WP-11。故障夹具与诊断 Schema 可提前准备，最终证据依赖实际集成。交付完整 AT-01..AT-20、24 小时四人长跑、状态分叉因果链、脱敏包、资源/性能数据、签名或可校验发行清单及回退手册。

发布必须没有未解释的持久分叉/无界资源增长，满足公布的硬件/城市/网络范围；未达到阈值就明确限制而不是改报告。只发布 Forge 及获许可的依赖，不含游戏 DLL、用户城市或密钥。关联 AT-18、AT-20。

## 4. 实际可并行的工作流

第一波：Core（WP-01）与 Runtime（WP-06）并行；Quality 先写事件模型和故障案例，不修改生产实现。第二波：Protocol（WP-02）、Storage（WP-03）在契约稳定后并行，同时 Runtime 完成隔离探针。第三波：Sessions（WP-04）、Transport（WP-05）、Domains（WP-07）按各自依赖推进。之后自然模拟、原生存档、兼容采集分轨，最后 Integration 合并真实能力。

并行代理/开发者使用独立 feature 分支，不多人同时改同一 DTO/版本注册文件。Core/Protocol 契约有单一集成负责人；依赖提交 SHA 固定，跨包变更先更新契约测试。合并前重放最新 develop 测试，禁止强推覆盖他人提交。

共享模拟世界仍然单写者，不能把“可以并行开发”和“可以多线程写游戏”混为一谈。开发任务拆分不是玩家加入串行化的借口。

## 5. 每个工作包的完成定义

必须同时具备生产实现、成功/拒绝/超时/取消/部分失败路径、直接运行生产代码的测试、资源上限、结构化诊断、接口文档与精确 CI/实机证据。带游戏/原生边界的包还需该层验证，不能只做 mock。

状态从 planned → implementing → model_verified → runtime_verified（适用时）→ integrated，只有具体证据允许升级。审查文档或创建空目录不算 implementing 完成；README 和状态索引必须诚实更新。功能开关不得在测试不足时默认开放。

## 6. 下一步执行点

从 WP-01 与 WP-06 两条独立线开始。纯代码线先实现逻辑成员/自然来源批次与读集版本；真实游戏线先完成合法引用构建和隔离探针。随后进入 WP-02/03，并以 WP-04 的并行加入模型验证作为第一个新增可运行结果。无需重新讨论已确定目标；只在实际引擎/传输证据推翻前提时更新相应 ADR。
