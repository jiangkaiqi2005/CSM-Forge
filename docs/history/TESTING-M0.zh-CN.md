## 本地与 CI 入口

```sh
dotnet build tests/Forge.Tests/Forge.Tests.csproj -c Release --nologo
dotnet run --project tests/Forge.Tests/Forge.Tests.csproj -c Release -f net8.0 --no-build
mono tests/Forge.Tests/bin/Release/net35/CSM.Forge.Tests.exe
```

第三行需要 Mono。Windows CI 目前不运行 Mono，也不伪装这一项成功。自定义测试执行器会逐项打印 PASS/FAIL；异常或找不到测试时返回非零退出码。CI 保留原始 native exit code，不用管道日志命令掩盖测试失败。

## 游戏接入的阻断性验收

| Gate | 必须取得的证据 | 当前 |
| --- | --- | --- |
| G0 加载 | 使用合法游戏 DLL 编译探针；ICities 加载/卸载稳定；核实真实 CLR/Unity/游戏版本 | 未测 |
| G1 客户端隔离 | 禁止权威模拟和本地持久写入，同时相机、UI、预览、渲染与所需调度继续正常 | 未实现/未测 |
| G2 结果闭包 | 基础参数及直道路创建/删除覆盖实体、引用、费用、分区块和缓存更新；无双重副作用 | 未实现/未测 |
| G3 加入/存档 | 保存切面、下载、加载、日志追赶、Ready；取消十次不残留任务/缓冲 | 未实现/未测 |
| G4 弱网络 | 两台独立游戏进程；不同延迟、丢包、乱序、断线；不继续错误编辑、不污染旧存档 | 未测 |
| G5 持续运行 | 两人暂停协作编辑的长时间场景；反复加入/退出；内存、带宽、队列和主线程耗时记录 | 未测 |
| G6 Mod 兼容 | 每个适配 Mod/版本逐操作测试，加载、批量操作、失败、重连、存档恢复均覆盖 | 未测 |

推荐故障矩阵条件为 0/100/300 ms 延迟，0/1/5% 丢包，重复与乱序，短时断网和超过超时阈值的断网。之后增加带宽限制、磁盘失败、满队列、低帧率主机/客户端、不同游戏版本和错误内容集。这些是验收输入，不是已经跑出的网络性能数据。

G1 失败时，停止扩展工具列表，先记录具体冲突的 Manager、线程和补丁组合；不能退回“让客户端全部模拟再偶尔校正”并仍称为同一稳定性方案。安全降级是限制为暂停编辑/只读、拒绝不支持的组合，或修订 ADR。

## 日志与诊断

当前 DiagnosticRing 保存有界的过程内单调时间、事件类别、Stamp、Peer、Revision、RequestId。测试异常保留堆栈在 CI；运行内核的隔离事件不会自动泄露原始报文或存档。它是第一层观测，不是完整生产诊断导出。

后续结构化 JSONL/诊断包需要加入 Domain、Schema、TransferId、阶段迁移、before/after 根、错误类别、耗时、队列深度、收发字节和支持的补丁指纹。保存首次可比较分叉及其前后有限事件，防止海量后续症状淹没真正原因。网络收到、队列接受、世界执行、结果提交、客户端应用、检查点发布使用不同事件名。

玩家导出必须主动选择并脱敏；不自动上传城市、账号、邀请码或密钥。发现同一版本反复分叉时触发恢复冷却/断开，不无限保存和下载。错误 UI 应说明是版本拒绝、连接超时、等待追赶、需要重装快照还是主机已隔离，而不是统一显示“连接失败”。

## 开发流程

小范围实现提交到 develop，每次完成边界和故障测试；CI 通过后快进 main。main 为可审核的开发基线，不代表玩家发行版。真正发行需要 G0–G5，宣称特定 Mod 兼容还需 G6。任何协议/Schema/游戏版本变更先写 ADR 或迁移说明。

当前只是工作流程和 CI，并未通过这次代码提交设置 GitHub 服务端分支保护/强制审查规则。构建不自动安装；游戏 DLL 不进仓库，私人存档不进公开测试夹具。以后需要原生传输构建时，单独记录依赖来源、版本、目标架构、许可证和产物摘要。
