# CSM-Forge 架构

## 权威模型

采用一个玩家游戏进程作为 Host 的单写者模型。Host 负责持久世界事实；Client 负责输入、预览与表现。正式协议不要求双方独立运行完整城市模拟。第一版不做自动 Host 迁移，也不将客户端世界升级为权威存档。

```text
客户端工具预览 / 主机本地工具
              │ Intent：想做什么 + 前置版本
              ▼
认证连接 → 兼容与权限 → 有界队列 → 主机模拟线程
                                      │ 验证并执行
                                      ▼
                   Commit：实际结果 + Revision + 状态根
                                      │
                        有界结果日志 / 可靠控制流
                                      ▼
                 客户端暂存、校验、发布 → Ready 屏障
                     │失败                 │正常
                     ▼                     ▼
                禁止编辑并恢复          表现层/UI
```

图中的传输、游戏工具、协调器和完整游戏适配器是待接入模块；当前已经实现中间的主机/副本状态机、参考领域、编解码和恢复算法，不能用图代替交付状态。

## 一致性单位与生命周期

WorldId 表示世界身份，Epoch 表示一次房间运行实例，Revision 表示本实例中已提交的权威结果序号。RequestId 是认证连接实例内单调递增的请求号，与网络包号、游戏 tick、存档版本不能混用。网络重连必须产生新的可信连接实例 GUID；报文不能自行指定其身份。

协调器应为新房间创建新 Epoch，并将世界标识、存档检查点和适配器 Schema 作为独立元数据保存；实现可使用强随机非零 Epoch，不能简单把每次启动都写成 1。当前内核接受外部提供的合法 Stamp，尚未实现房间持久身份管理。

HostSession 只在认可一个世界结果后增加 Revision。拒绝且未修改世界不增加 Revision；已处理的版本冲突/领域拒绝有稳定回执。重复请求返回相同已记录结果，不能再次执行；回执淘汰后仍以请求高水位拒绝旧请求。该保证限于当前进程和连接实例，**不是跨崩溃 durable exactly-once**。

当前参考领域使用整个世界的 ExpectedRevision，刻意采用保守冲突控制。道路阶段应扩展到明确的对象代次、读写集和局部前置版本，避免不同区域编辑互相拒绝；扩展必须升级 Schema，不能偷偷改变现有字段语义。

## 持久状态、派生状态、表现状态

持久/游戏事实：道路拓扑、建筑、分区、政策、经济余额、资源、实体生命周期，以及参与未来决策的模拟状态。只接受 Host 的有序结果。

可重建状态：缓存、空间索引、某些渲染资源。由适配器在完整数据发布后按受控顺序重建，不逐字段随意覆盖。是否真的可重建必须依据游戏行为验证。

表现状态：远端指针、工具预览、相机、经过验证只用于表现的车辆/行人位置。允许独立的低优先级不可靠 sequenced 更新及插值；不能把近似显示结果写回权威资金、寻路或存档。

车辆/行人不仅有位置。未来开放真实时间模拟时，其产生、消失、任务和经济关联等游戏事实必须进入权威复制闭包。把客户端车流继续独立运行、只同步道路和资金，不满足本架构的正确性声明。

## 结果、实体 ID 与原子性

Intent 表达玩家愿望，例如“在这些控制点创建某类道路”；Commit 表达主机已经决定并完成的拓扑、实体和费用结果。客户端不得重跑整个 NetTool 入口来猜测同样结果。

道路适配器设计采用逻辑 64 位实体 ID 加 generation，再映射本地游戏句柄。删除后的 ID 重用、节点/路段/分区块引用和 Mod 扩展状态纳入 Schema。Prefab 使用稳定内容身份而非仅使用显示名称。该映射和闭包目前还没有实现。

引用领域能构造完整候选状态并一次交换。游戏 API 未提供已验证的跨 Manager 事务，因此适配器不能保证的回滚不得写入接口承诺。流程为：尽量预验证、定义发布边界、捕获完整结果；出现任何可能部分生效的异常，隔离世界。Host 进入 fenced 后停止写入、入房确认和新快照发布；Client 进入 NeedsSnapshot，后续普通 Commit 不再执行。

主机自身也会验证实际状态是否仍等于最近已提交状态根。周期 VerifyWorld、执行前、快照前和入房确认都覆盖这条防线。检测覆盖依赖适配器的规范化状态范围，不等于能观察未建模的所有 CS1 字段。

未来主机自然模拟产生的变化也必须在安全边界形成有序权威结果；它不能绕过日志。当前 HostSession 尚无真实城市模拟 tick 的 capture/commit 适配，不能直接接入一个持续自行改变的游戏世界再宣称正常工作。

## Snapshot、Delta、加入与恢复

快照必须是某个明确 Revision 的一致切面。当前内核在 owner 线程同步 Capture，并验证前后根和内容摘要；实际 CS1 保存可能异步完成，协调器必须建立短暂停写/安全点，完成不可变快照后才恢复。未完成这一适配前，不允许把任意异步 .crp 文件标为某个实时 Revision。

初次加入顺序：传输认证 → 固定 Bootstrap/兼容检查 → 授予世界身份与只读会话 → 下载快照 → 内容校验 → 游戏加载与语义根校验 → 补快照之后的连续 Commit → Host 校验同一 Revision/根 → 发送 Ready 屏障 → 开放受支持的工具。下载完毕和 TCP/UDP 连接建立都不等于可以修改城市。

普通增量采用绝对结果，降低重复累加风险。日后做压缩 Delta 时，必须带客户端已确认的明确 baseline，失去 baseline 则重新发送绝对结果；不能拿“最近发出的包”冒充“对方已拥有的状态”。

当前恢复内核实现三条路径：连续缺口在 512 条提交保留窗口内补日志；窗口外重新快照；状态根不匹配或应用失败立即要求快照。恢复采用新的 TransferId，过期快照回调、不同 Epoch 和低于已接受 Revision 的快照都不能覆盖当前副本。快照之后仍需要匹配的 Ready 屏障。

分片接收器支持磁盘临时流、乱序接收、重复一致性检查、单块及全文件校验与取消释放。SHA-256 ContentHash 用于文件完整性；StateHash 用于规范化游戏事实一致性，两者不能混为一谈。当前参考世界最大 64 MiB、块最多 8192、块最多 32 KiB；这不是大型真实城市的支持声明。后续提高限制要同时增加磁盘配额、传输窗口和超时预算测试。

当前这些算法之间尚缺正式网络/加载协调器。PeerLiveness 只给出健康状态，不能自行关闭真实 socket；SnapshotAssembler 也不会自行保存或加载游戏。协调器必须在断线、超时、切图和取消时串联这些行为。

## 存档与崩溃恢复

只有 Host 创建正式检查点。计划将原生城市存档和 Forge 元数据（世界身份、检查点 Revision、领域 Schema、组件与内容指纹、实体映射、内容摘要）一起写入临时检查点目录，经校验后以同文件系统发布操作提交，保留上一有效检查点。实际刷盘和目录原子发布语义需要针对支持平台验证，当前尚未实现检查点存储器。

普通 Commit 表示当前运行实例中已接受的世界结果；只有 checkpoint-published 才表示可恢复的存档点。主机崩溃后恢复上次有效检查点并启动新 Epoch，旧连接及未明确完成请求不自动重发；UI 必须说明可能丢失检查点后的操作。不宣称仅凭内存日志可以精确恢复任意游戏模拟。

Host 发生部分失败时禁止直接把污染世界导出为新的恢复基线。恢复来源只能是先前验证的检查点，或用户明确退出联机后单独处理的本地副本。第一版不尝试自动 Host 选举或分裂房间合并。

## 模块边界

| 模块 | 当前内容 / 责任 | 不应承担 |
| --- | --- | --- |
| Forge.Core | HostSession、ReplicaSession、世界接口、完整性值、恢复和兼容策略、有界诊断 | Unity、Harmony、socket 回调、游戏程序集 |
| Forge.Protocol | 有界固定版本帧、Intent/Commit 编解码 | 动态类型注册、游戏方法调用、身份认证假设的实现 |
| Forge.Runtime.Cities1 | 当前仅 ICities 加载探针；以后是生命周期、游戏线程入口和适配器组装 | 自己定义第二套提交顺序、绕过内核的玩家修改 |
| 正式 Transport 适配器（未实现） | 可信连接实例、可靠控制流、独立 bulk lane、加密和连接统计 | 世界 Revision 分配、游戏原子事务 |
| 房间/会话协调器（未实现） | Bootstrap、权限、兼容采集、加载/补齐/Ready/恢复流程、超时资源回收 | 把网络 ACK 解释为世界提交 |
| 领域适配器（未实现） | 道路/建筑/经济等完整结果与规范化状态、实体映射、原生存档桥 | 隐藏全局静态 Ignore 开关和无限容错回放 |
| Forge.Tests | 直接引用生产内核和编解码，外部边界故障注入 | 修改生产代码后测试、伪造游戏验收 |

核心接口：`IAuthorityWorld.Execute/Capture/StateHash`、`IReplicaWorld.Apply/Install/StateHash`。只有 owner 线程访问世界；网络线程把不可变消息投递到 BoundedInbox，满时背压/拒绝，不以增长内存应付慢端。核心目前拒绝重入；真实适配器中的嵌套游戏调用应使用每次调用的作用域所有权，而不是全局 Reset。

## 传输、安全与易用性

正式传输首选独立 GameNetworkingSockets。Control lane 使用可靠有序传输；Bulk lane 限速并设置低于控制流的优先级；Presentation lane 可丢弃过时数据。原生接口加载和发行打包要验证，不直接依赖某个要求 netstandard 的 C# binding，也不替换游戏自身 steam_api。

互联网易用性的产品路线是自动启动连接服务、房间邀请码、自定义信令和直连优先、失败转可运营的中继。邀请码是发现方式，不是长期身份凭据；需要独立的短期认证授权及滥用限流。不得假设免费获得 Steam SDR。当前没有部署房间服务、中继或实现网络认证。

当前帧摘要仅防损坏，不防能重算摘要的攻击者。实际传输必须建立经认证且加密的端到端身份；短期授权、速率/连接数、消息类别、权限和会话阶段共同校验。未知消息/版本、过长内容和无效分片在进入世界层前拒绝。日志不保存房间密钥、完整原始报文、存档或自动上传私人城市。

## 兼容与演进

代码版本、协议版本、状态 Schema 版本、游戏版本和 Mod 支持目录分开管理。当前 v1.0 采用精确匹配，未知版本拒绝，不静默降级。未来 minor 扩展也必须显式协商能力，存档迁移使用离线备份和已测试迁移器。

CompatibilityPolicy 接受维护者建立的必需组件和已审核可选本地组件目录，检查二进制及配置摘要；必须同时验证 Host 和 Client。不能用 Host 当前装了什么自动生成“已兼容”白名单，也不能让客户端自报无害类别。HostOnly、ToolOnly、ClientOnly、共享模拟和共享资产是适配支持证据的结果，而不是凭 Mod 名称推断的永久标签。

第一版从原版环境开始。其他 Mod 按操作和版本做能力适配，测试创建/删除/批量/失败/存档/重连；未验证则禁止，而不是向玩家承诺“尽量兼容”后继续运行。

## 性能策略

参考世界使用完整小状态哈希用于验证不变量；真实城市不能每个命令全量扫描。后续领域维护增量脏集和版本化分区根，在明确一致切面冻结/比较；进行完整校验时有工作量预算。跨不同 tick、不同 Revision 或变动采样窗口的哈希不得用于确定 desync。

网络成本以持久变更和可见表现更新为主，不逐帧广播整个城市。提交日志、回执、分片、诊断和队列都有上限；慢客户端优先进入追赶/重新快照，超过预算则断开，不无限拖住整个房间。每帧处理预算、带宽、长时间稳定性和大型城市容量都是后续实测验收指标，不在没有数据时给出性能保证。
