# 并行加入与无全房等待协议

规范版本：2.0-design。关联需求：F-JOIN-01、F-JOIN-02、F-JOIN-03、F-JOIN-04、F-REC-02、F-LOAD-01。新增行为尚未实现。

## 1. 并行的精确定义

场景基线：Host A 与玩家 B 正在游玩，C、D 在时间上重叠地连接、下载、加载并追赶。C 完成后可先进入；D 不必跟 C 一起完成。D 取消不能清空 C 的结果日志、暂停 A/B、重置整个房间或销毁仍被 C 使用的快照。

必须并行的部分是每个独立客户端的传输、加载和追赶；必须串行的部分是 Host 世界修改、同一 Client 游戏进程的 Load/Unload，以及游戏 API 不支持并发时的快照生成。一个共享快照生成器不等于一个全局串行加入队列。

产品默认至少允许两个进行中的加入流程。安全容量不足可以在大文件传输前拒绝/排队新请求，但必须显示容量原因，不得把“所有客户端必须按顺序加载”作为常规设计。

## 2. 身份、对象与所有权

| 身份 | 生命周期 | 用途 |
| --- | --- | --- |
| WorldId + Epoch | 当前权威世界实例 | 隔离重开房间、回滚和换图 |
| MemberId + MemberGeneration | 已授权的逻辑玩家席位 | 权限和操作账本，不直接等同于 socket |
| ConnectionBinding | 每次可信连接重新建立 | 旧连接回调和新连接分离 |
| JoinId + JoinGeneration | 一次加入/重新基线化尝试 | 定位状态机；失败重试创建新代次 |
| SnapshotId | 一个不可变内容产物 | 允许多个 JoinContext 共享 |
| TransferId | 一个 JoinContext 的文件传输 | 进度、分片确认与取消独立 |
| LoadGeneration | Client 进程当前加载任务 | 防止旧 OnLevelLoaded 回调污染新世界 |
| BarrierId / GrantId | 一次固定追赶屏障/激活授权 | 防重放，不由客户端任意决定 |

SnapshotId 与 TransferId 不能合并。SnapshotHandle 只含不可变元数据、流打开能力和资源租约，不共享一个可变 Stream.Position；每个发送者有独立读取游标。取消单个 Transfer 不删除公共文件；最后一个引用释放且不再用于恢复/保存后，由缓存策略回收。

房间拥有全局 CheckpointCatalog、CommitStore、AdmissionController 和预算；每个 Member 拥有自己的 JoinContext、重试计数、流量/进度、租约和诊断上下文。不得设置全局“当前下载玩家”“当前 sender”字段供异步回调读取。

## 3. 前提与一致性证明范围

只有 Host 能提交；每个 Commit 表示完整结果批次，并保存其发布后的规范化根。结果覆盖加入所需的所有持久事实及必要派生重建信息。Checkpoint 的 B 与原生游戏保存切面一致。网络/磁盘/应用队列均有界。

若尚不能在真实游戏中满足这些前提，内核模型仍可测试，但功能标记为未通过游戏验收。不会用“先发一个旧存档，再把玩家点过的按钮补发一遍”冒充完整的自然模拟追赶。

## 4. 原子建立快照基线和日志订阅

在 Host owner-thread 的一个线性化步骤执行：

```text
检查 Epoch / 容量 / 支持目录
选取已发布快照 S，其基线为 B
确认 (B, currentHead] 的日志仍连续且可保留
取得 S 的引用和从 B+1 开始的有限 retention lease
注册 JoinContext 的日志游标与有序状态输出
向客户端发布 SnapshotOffer(S, B, rootB, manifest)
```

任何失败撤销本次引用和租约；未完成步骤不得向客户端宣称 offer 已可用。不能先发送快照信息，再异步注册增量订阅：中间的 Commit 会永久丢失。

优先复用最近一次已验证检查点。多人同时请求新的兼容快照时，对相同内容上下文 single-flight 合并生成任务，而不是每人调用一次原生保存。等待产物的客户端可以独立取消。只在所有引用取消、且生成工作未被其他检查点用途持有时，才取消生成器。

缓存已失效或日志将越界时，要么生成新检查点后重定基线，要么明确拒绝新加入；不能一边继续下载已不可能追赶的基线，一边无界增加内存。

## 5. 快照生产与主机不停玩的边界

下载和 Client 本地加载不要求 Host 停止。快照创建本身必须得到一致切面，不能让工作线程无锁读取正在变化的游戏数组。

首条实现路线：在经验证的模拟安全点冻结本次保存需要的不可变状态/原生保存输入，尽早释放世界写屏障，再在工作线程压缩、摘要、写盘和发送。原生序列化是否已经冻结数据需要实测，不因 API 名字带 Async 就默认安全。

在尚无可用短安全点的版本，允许使用已发布且日志仍覆盖的旧检查点提供并行加入。若必须执行长时间同步保存，UI 标明是主机本机快照开销；不得称其为“零停顿热加入”，更不能把暂停延长到所有客户端下载/加载完成。此限制是快照能力的验收缺口，不是删除并行加入目标的理由。

Factorio 的异步保存示例利用特定平台的 fork，并不是可直接复制进 Windows CS1 的通用机制。[S-FACTORIO] Forge 不通过 fork 克隆游戏进程实现该功能。

## 6. 每个加入者的状态机

```text
Connecting → Authenticating → Negotiating → Admitted
 → SelectingSnapshot → Downloading → VerifyingContent
 → Loading → VerifyingWorld → CatchingUp → AwaitingActivation → Live
```

任何阶段可进入 Cancelling → Closed；可恢复错误先进入 RecoveryPending，释放旧绑定后创建新 JoinGeneration。Rejected、Expired、Closed 为终态，不复用旧状态对象。

| 阶段 | 允许的输入 | 不能做的事 |
| --- | --- | --- |
| 认证/协商 | 固定 Bootstrap、身份挑战、支持清单 | 接收游戏指令、加载远端内容 |
| Downloading | 本 Transfer 的有效分片、取消、存活信号 | 写游戏世界；把其他 Transfer 数据拼进来 |
| Loading | IO 生命维持、受限日志落盘、当前加载进度 | 在旧城市中应用新世界 Commit |
| CatchingUp | 连续状态结果和屏障 | 开放持久编辑、跳过失败结果 |
| AwaitingActivation | 固定授予、其前序结果、取消 | 因 socket 连上或下载完成就启用工具 |
| Live | 授权意图、结果、检查点与观测 | 本地越过主机直接修改世界 |

加载期间网络工作者继续轮询，但仅将结果保存到有界临时日志或网络队列。游戏应用只能在当前 LoadGeneration 加载完成且语义基线匹配后开始。只靠网络线程持续发心跳不能证明加载任务正在推进。[S-STEAM]

## 7. 固定水位屏障与激活：避免永远追赶当前头

符号：B 是快照基线，H 是本次固定校验水位，A 是激活授予所在的固定发布边界。满足 B ≤ H ≤ A；主机当前头可以继续超过 A。根 Root(H) 与 Root(A) 在租约/授权有效期内不可被悄悄淘汰。

### 7.1 设置 H

Client 安装并验证 B 后，按连续顺序应用结果。Host 根据该 JoinContext 的进度，在 owner-thread 选定 H = 当时已提交头，并保存 `(BarrierId, H, Root(H), leaseDeadline)`。在该 Client 的 STATE 有序流上，先发完必要的 B+1..H，再放入 Barrier(H)；后续 H+1.. 的提交仍进入同一流。

Barrier 不是暂停消息，也不是“现在等所有人”。每个加入者有自己的 H。重复发送同一 BarrierId 必须带相同内容。

Client 不得越过一个尚未应用的 Commit 处理 Barrier。到 H 时完成游戏投影发布，计算/读取这一一致切面的根，保存根证据，再通过 CONTROL 发 `BarrierAck(JoinIdentity, BarrierId, H, Root(H))`。Client 可以在保留 H 证据之后继续应用 H+1..；不能在已经应用更高版本后重新计算当前根来冒充 Root(H)。

### 7.2 校验历史水位，不比较移动中的当前头

Host 校验 Ack 的来源、JoinGeneration、BarrierId、H、Root(H)、租约和日志连续性。**不要求 H 等于此时 Host.Revision。** 可比较根来自此前保存的 H，不是最新世界。若根已过保留期，返回 BarrierExpired，而不是把当前根拿来比较。

Host 还检查该连接的实际落后量、积压字节、进展速度和授予预算。安全校验通过但连接持续追不上时不授予编辑；执行慢端策略。不能无限重新选择更远 H，使正常网络往返永远赶不上。

### 7.3 授予 A 与生效顺序

在一个 owner-thread 步骤内，Host 选择 A = 当时提交头，记录 `GrantId, MemberGeneration, JoinGeneration, ConnectionBinding, A, Root(A), permissionVersion, deadline`。向同一 STATE 流排入 A 之前尚未发完的结果，再排 ActivationGrant(A)，然后继续 A+1..。本步骤建立实时订阅，不存在“发完历史，再另建实时监听”的空窗。

跨通道没有到达顺序保证。因此 ActivationGrant 在 STATE 流内定位，不能仅在更高优先级 CONTROL 流抢先通知“已加入”。有序传输也只保证消息到达顺序；本地应用队列仍要等 A 真正发布后处理 Grant。[S-LANES]

Client 只有在以下条件全满足时进入 Live：当前 Epoch/绑定/Join/LoadGeneration 未变化；已连续应用至 A；根验证通过；Grant 尚未过期/撤销；没有等待中的 gap、恢复、加载或本地隔离。然后发送 `Activated(GrantId, A)`；Activated 与其后玩家意图沿同一可靠 CONTROL 顺序发送。

Host 收到有效 Activated 后把该成员从 AwaitingActivation 转为 Live。任何抢先到达或旧 Grant 的意图被拒绝。收到 Activated 时不要求 A 等于最新头，但仍检查落后预算与 token 期限。接下来正常意图以对象/读集版本再次裁决，不把 Live 资格解释为对过时状态的无限写权限。

### 7.4 完整性理由

B 的快照和 B+1 的保留订阅原子衔接，防止初始化窗口漏消息；按连续结果应用保证可归纳得到正确 S_H；H 的历史根验证避免移动目标；A 前结果和 Grant 在同一状态序列上有序，防止授权早于游戏状态；过期绑定/代次拒绝防止晚回调复活旧世界。

这是在适配器完整性、正确消息来源、有限故障与足够处理能力前提下的设计论证，不是已验证的 CS1 正确性证明，也不是拜占庭容错协议。恶意客户端可以谎报根，但仍不能越过主机的工具验证修改城市。

## 8. C 与 D 并行加入的时序例子

```text
Host 当前 R=100：获取共享快照 S100，分别为 C/D 取得租约
Host 继续运行并提交 101..180
C 下载并加载完成，应用至 Hc=180，验证并回 Ack
D 仍在下载；只占用 D 自己的传输窗口
Host 到 R=195：核对保存的 Root(180)，为 C 排入 Grant(Ac=195)
C 应用至 195 后生效；Host/旧玩家/C 继续游玩
D 取消：释放 D 的租约/文件游标，不清空 C 或 Host 的状态
```

H 和 A 是两个固定检查点，不要求两端在同一墙钟时刻状态一样。若 D 没取消，它可以稍后获得自己的 Hd/Ad；也可以因落后预算超限重新取得较新快照。不能为了 D 清理公共日志到 C 尚未确认的位置之前。

## 9. 追赶能力、日志保留和公平性

不能保证无限慢的机器一定加入。用字节或估计应用工作量而非只用条数估计：Host 生成速率 λ、Client 持续应用能力 μ、初始积压 Q。当 μ > λ 且带宽足够时，近似追赶时间 Q/(μ−λ)；μ ≤ λ 时，单靠重复追赶不会收敛。该公式是容量推导，不是实测数据。

策略顺序：减少/停发可丢弃表现流 → 给追赶安排剩余应用预算与公平带宽 → 在容量内选较新基线 → 有界重试 → 返回 ClientCannotKeepUp 或只读且有时限的恢复状态。只读不是无限堆积的许可；读取也持续落后则断开。

保留策略同时约束日志字节、时间和租约寿命。最老游标可以 pin 一段日志，但不能无限阻止回收。预算即将超过时，先撤销进展最差的加入租约，给明确重基线原因；不牺牲已正常运行的玩家。离开、被踢、切图、Epoch 变更均释放其租约。

调度需房间级公平轮询与每 Peer 背压。严格高优先级流如果持续非空，低优先级 bulk 会饿死；不能只写“快照低优先级”就认为已解决。采用受限紧急控制配额、STATE/BULK 同级权重加最小剩余服务；已超载时拒绝新加入而不是许诺不存在的最低带宽。[S-LANES]

## 10. 取消、重连、重复和竞态

取消线性化点在 JoinCoordinator：先标记终态并撤销授权，再取消各工作者、释放读句柄和租约。工作者完成回调先比对全部 identity/generation，再入队；owner-thread 执行前再核对一次。Dispose/Cancel 可重复调用，不得重复归还公共引用。

同一成员的重连：重新认证并生成新 ConnectionBinding；旧绑定即刻撤销。操作账本可保留于逻辑成员，但快照传输必须重新校验身份和内容。断点续传仅对完全相同 SnapshotId/内容哈希/块布局且磁盘块再次校验后开放；它不是跳过授权的通行证。

回调顺序必须覆盖：取消先于磁盘完成、磁盘完成先于取消、加载结束晚于切图、旧连接断线晚于新连接激活、同一客户端重复 JoinRequest、快照刚被选中就触发回收。重复请求用稳定 CorrelationId 返回相同已接受状态或明确过期，不创建第二套无限任务。

## 11. 禁止实现与验收

禁止全局 isJoining；禁止每个 Client 独立触发整份原生保存；禁止边载入旧城市边应用新世界结果；禁止拿“已发送的 revision”当“Client 已应用的 revision”；禁止低于基线的回调回滚副本；禁止单个下载超时暂停全房；禁止把缺少历史根解释为“不匹配，重试直到成功”。

必须通过 AT-05..AT-10、AT-14..AT-15，包括 Host 持续提交时的两个并行加入者、一个取消一个成功、固定 H 的往返期间 Host 继续推进、日志淘汰和跨通道重排。协议字段与预算参见 [协议](PROTOCOL-V2.zh-CN.md)、[鲁棒性](ROBUSTNESS.zh-CN.md)；来源见 [索引](SOURCES.zh-CN.md)。
